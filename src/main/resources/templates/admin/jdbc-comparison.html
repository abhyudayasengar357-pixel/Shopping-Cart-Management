1. Traditional JDBC Implementation
Manual Boilerplate

From TraditionalJdbcProductRepository.java: Requires manual Connection opening, PreparedStatement binding, ResultSet cursor iteration, and checked SQLException handling. 

// Traditional JDBC Method (Actual Project Code)
public Optional<Product> findById(Long id) {
    String sql = "SELECT * FROM products WHERE id = ?";
    // 1. Manually open connection via DriverManager
    try (Connection conn = DriverManager.getConnection(url, user, pass);
         PreparedStatement ps = conn.prepareStatement(sql)) {

        // 2. Set parameter indices manually
        ps.setLong(1, id);

        // 3. Execute query and obtain ResultSet
        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) {
                // 4. Manually extract and map every column
                Product p = new Product();
                p.setId(rs.getLong("id"));
                p.setName(rs.getString("name"));
                p.setPrice(rs.getBigDecimal("price"));
                p.setStockQuantity(rs.getInt("stock_quantity"));
                return Optional.of(p);
            }
        }
        return Optional.empty();
    } catch (SQLException e) {
        // 5. Must handle checked SQLException manually!
        throw new DatabaseOperationException("JDBC error", sql, e);
    }
}
2. Spring JDBC (JdbcTemplate)
Modern Spring Framework

From SpringJdbcProductRepository.java: Uses Spring's JdbcTemplate, reusable RowMapper, pooled HikariCP DataSource, and automatic unchecked exception translation. 

// Spring JDBC Method (Actual Project Code)
public Optional<Product> findById(Long id) {
    String sql = "SELECT * FROM products WHERE id = ?";
    try {
        // 1. Connection acquired automatically from pool
        // 2. PreparedStatement prepared safely
        // 3. RowMapper<Product> maps rows declaratively
        // 4. Connection closed automatically back to pool
        Product p = jdbcTemplate.queryForObject(
            sql,
            productRowMapper,
            id
        );
        return Optional.ofNullable(p);
    } catch (EmptyResultDataAccessException e) {
        // 5. Unchecked Spring DataAccessException hierarchy
        return Optional.empty();
    }
}

Connection Management Manual creation via DriverManager.getConnection(). Opens a new physical TCP connection per call if unpooled. Automatic connection pooling managed via HikariDataSource. Connections are reused efficiently.
Boilerplate Code High. Requires opening, parameter setting, cursor iteration, and manual resource closing. Minimal. JdbcTemplate encapsulates repetitive boilerplate in template callback methods.
Exception Handling Throws checked java.sql.SQLException. Requires explicit try-catch or method signature decoration. Translates SQLExceptions into rich, unchecked org.springframework.dao.DataAccessException hierarchy.
Object Mapping Manual column reading using rs.getString(), rs.getBigDecimal() in loops. Declarative mapping using reusable RowMapper<T> functional interfaces.
Transaction Management Manual control: conn.setAutoCommit(false), conn.commit(), and conn.rollback(). Declarative transaction management via Spring's @Transactional annotation.
SQL Injection Defense Supported via PreparedStatement placeholders (?), but developer must be diligent. Built into JdbcTemplate methods via varargs parameter binding.
University Viva Preparation: Frequently Asked Questions

Traditional JDBC requires extensive repetitive boilerplate: opening connections, managing prepared statements, manually looping over result sets, and closing resources in finally blocks. Additionally, traditional JDBC throws checked SQLException, coupling persistence details with business layers. Spring JDBC uses the Template Method pattern (JdbcTemplate) to eliminate boilerplate, reuse connections from HikariCP, and translate exceptions into unchecked DataAccessException.

In TraditionalJdbcAuditRepository.java, we demonstrate manual transaction control: we set conn.setAutoCommit(false), execute the SQL statement with a prepared statement, invoke conn.commit() upon success, and in the catch block explicitly call conn.rollback() before resetting auto-commit.

In OrderService.placeOrder(), the method is annotated with @Transactional(rollbackFor = Exception.class). Within a single transaction boundary: the cart items are verified, simulated payment is authorized, order and order items are inserted, and product inventory quantities are decremented. If any step fails (e.g. insufficient stock or payment failure), the entire transaction rolls back automatically, preventing orphaned orders or incorrect stock levels.
